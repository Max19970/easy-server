# Политика безопасности

**Язык:** [English](SECURITY.md) · Русский

Сообщайте о предполагаемых уязвимостях EasyServer приватно. **Не** создавайте публичную GitHub issue для ещё не раскрытой проблемы безопасности.

Границы доверия продукта и его предположения о безопасности отдельно описаны в [модели безопасности EasyServer](docs/ru/security-model.md).

## Поддерживаемые версии

Пока `0.2.x` является текущей выпущенной линией совместимости, исправления безопасности ориентированы на последнюю выпущенную версию `0.2.x`.

Линия `0.1.x` больше не получает общее сопровождение. Критические исправления безопасности или целостности данных могут быть backport-нуты по решению мейнтейнера, но бессрочная поддержка этой линии не обещается.

Невыпущенные development snapshots не считаются поддерживаемой release line.

Более широкие правила сопровождения описаны в [политике поддержки и сопровождения](docs/ru/support-and-maintenance.md).

## Как сообщить об уязвимости

Используйте GitHub Private Vulnerability Reporting для этого репозитория:

1. Откройте раздел **Security** репозитория.
2. Выберите **Report a vulnerability**.
3. Укажите затронутую версию EasyServer/пакета, окружение, влияние и шаги воспроизведения.
4. Приложите только минимально необходимую чувствительную информацию для воспроизведения проблемы.

Не включайте реальные API keys, приватные SSH-ключи, пароли провайдеров, daemon bearer tokens или несвязанные данные аккаунта/провайдера. По возможности используйте отредактированные или синтетические значения.

## Раскрытие и исправление

Отчёты исследуются и исправляются по мере доступных ресурсов. EasyServer не обещает фиксированный SLA на подтверждение или устранение уязвимости.

Пока проблема оценивается, координируйте раскрытие через приватный отчёт. Изменения безопасности, затрагивающие совместимость выпущенной версии, документируются в соответствующих release notes.
