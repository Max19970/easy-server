# Начало работы

**Язык:** [English](../getting-started.md) · Русский

Это руководство проведёт вас от чистой установки EasyServer до первого полезного результата: сервис, запущенный на арендованном сервере, станет доступен на вашем собственном `localhost`.

Для начала не нужно разбираться в daemon EasyServer, модели сохранённых подключений, внутренних ID или контрактах плагинов. Всё это описано в более подробных руководствах — к ним можно перейти, когда понадобится.

## Перед началом

EasyServer `0.2.0` квалифицирован для **Windows 11 x64**. Начиная с `0.2.1`, квалифицированные client targets — **Windows 11 x64**, **Ubuntu 24.04 x64** и **macOS 15 arm64** с **Node.js 24.18.1**. Подключения через SSH используют системный клиент OpenSSH.

Если ваша среда отличается от квалифицированной конфигурации релиза, проверьте полные требования в разделе [Поддерживаемые платформы](supported-platforms.md).

Также нужна учётная запись и учётные данные хотя бы одного поддерживаемого провайдера:

- [Vast.ai](providers/vastai.md)
- [Intelion.cloud](providers/intelion.md)

## 1. Установите EasyServer

Установите основной пакет CLI:

```powershell
npm install --global @easyai101/easyserver
```

Затем установите один плагин провайдера. Для Vast.ai:

```powershell
npm install --global @easyai101/easyserver-plugin-vastai
```

Или для Intelion.cloud:

```powershell
npm install --global @easyai101/easyserver-plugin-intelion
```

Чистая установка основного пакета по умолчанию не содержит провайдеров. Начиная с `0.2.2`, для каждой квалифицированной платформы также публикуется переносимый артефакт GitHub Release; следуйте руководству [Установка из GitHub Releases](github-release-install.md) и устанавливайте плагины в этот распакованный prefix EasyServer.

## 2. Откройте TUI

Запустите EasyServer без аргументов:

```powershell
easyserver
```

Обычный `easyserver` — стандартная точка входа в интерактивный режим. CLI остаётся доступной для автоматизации и расширенных сценариев через `easyserver --help`.

При первом запуске полезный путь такой:

**Settings & Support → Providers → Add installed provider**

Выберите установленного провайдера. EasyServer читает метаданные провайдера из пакета, поэтому его можно выбрать по имени, не вводя путь к модулю вручную.

## 3. Настройте учётные данные провайдера

Откройте **Actions** провайдера и выберите действие настройки учётных данных. Во время ввода TUI скрывает значение.

EasyServer хранит учётные данные провайдера через Secret Store операционной системы; в обычном Local State сохраняется только непрозрачная ссылка на секрет.

Названия учётных данных зависят от провайдера:

- Vast.ai: `api-key`
- Intelion.cloud: `api-token`

В руководствах по конкретным провайдерам объясняется, откуда получить эти учётные данные и какую подготовку аккаунта следует выполнить до аренды.

Если вместо TUI вы автоматизируете настройку, эквивалентный CLI-сценарий импортирует значение из переменной окружения. Точные команды приведены в руководстве соответствующего провайдера.

## 4. Арендуйте сервер

Вернитесь на **Home** и выберите **Rent a server**.

Выберите провайдера и следуйте его пошаговой форме. EasyServer намеренно оставляет получение ресурса специфичным для провайдера:

- Vast.ai предоставляет свой marketplace и параметры аренды.
- Intelion.cloud предоставляет свой поток конфигурации/каталога серверов.

TUI показывает реальные параметры конкретного провайдера, а не делает вид, что оба сервиса используют одну универсальную форму создания. Перед выполнением платных операций отображается экран подтверждения.

Подробности об образах, GPU-фильтрах, flavors, настройках диска, подготовке SSH-учётной записи или особенностях биллинга провайдера ищите в соответствующем руководстве, а не подбирайте значения наугад:

- [Аренда через Vast.ai](providers/vastai.md)
- [Создание через Intelion.cloud](providers/intelion.md)

## 5. Дождитесь готовности сервера

Откройте **Servers** и выберите сервер, который вы только что создали или арендовали.

Состояние у провайдера может сходиться не мгновенно. Используйте только те действия жизненного цикла, которые EasyServer действительно показывает для текущего состояния сервера, вместо предположения, что любое действие допустимо всегда.

Когда нужная рабочая нагрузка запущена на сервере, определите её TCP-порт. Например, ComfyUI часто слушает порт `8188`.

EasyServer не устанавливает и не запускает эту рабочую нагрузку за вас; он управляет вычислительным ресурсом и границей подключения вокруг неё.

## 6. Подключите сервис к localhost

Выберите сервер и нажмите **Connect**.

Введите **порт приложения/сервиса на сервере** — например `8188`. В обычном сценарии локальный порт может быть выбран автоматически.

При первом SSH-подключении EasyServer показывает fingerprint SSH host key сервера. Проверьте его и явно выберите **Trust**, если он соответствует ожидаемому серверу. EasyServer ведёт собственное хранилище доверенных SSH-ключей; доверие, подтверждённое отдельной командой `ssh`, автоматически не импортируется.

После открытия подключения EasyServer выдаёт локальный адрес, например:

```text
127.0.0.1:54321
```

Если удалённый сервис работает по HTTP, откройте этот адрес в браузере. Для примера с ComfyUI:

```text
http://127.0.0.1:54321
```

Теперь основной сценарий EasyServer работает от начала до конца: аренда через нативный для провайдера поток, общее управление сервером и локальный доступ к удалённому сервису.

## Если первое подключение не удалось

EasyServer разделяет типичные уровни сбоев, чтобы не сводить любую проблему к «сервер недоступен». TUI умеет различать, например, такие случаи:

- SSH host trust всё ещё требует проверки;
- SSH login key/password отклонён;
- SSH-маршрут запрещает TCP forwarding;
- SSH работает, но порт приложения/сервиса не слушается или недоступен;
- запрошенный локальный порт уже занят.

Используйте действие восстановления, которое предлагает TUI, — например **Review SSH fingerprint**, **Edit service port**, **Edit local port**, **Retry connection** или **Open Diagnostics**.

Полная модель подключений и CLI-эквиваленты описаны в разделе [Подключение к удалённому сервису](connections.md).

## Прежде чем оставить платный сервер работающим

Закрытие EasyServer или отключение плагина провайдера **не** уничтожает ресурс у провайдера. Остановленный сервер также не означает автоматически, что начисление платы прекратилось.

Когда сервер больше не нужен, выполните очистку по руководству провайдера и убедитесь, что ресурс достиг нужного конечного/отсутствующего состояния:

- [Очистка Vast.ai](providers/vastai.md)
- [Очистка Intelion.cloud](providers/intelion.md)
