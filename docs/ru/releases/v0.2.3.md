# EasyServer 0.2.3

Дата версии: **2026-08-18**

EasyServer `0.2.3` — обратно совместимый TUI/QoL- и code-health-релиз линии `0.2.x`. Он сохраняет принятую task-first модель взаимодействия, но делает повседневную работу в терминале спокойнее, понятнее, визуально цельнее и устойчивее к ошибкам подключений и провайдеров.

Миграция с `0.2.2` не требуется. Существующие корректные Local State `0.2.x`, Secret References, сохранённые фоновые подключения, CLI-сценарии и Provider Plugins, объявляющие совместимость `^0.2.0`, остаются валидными. Настройки внешнего вида TUI опциональны и хранятся отдельно от Local State.

Эта страница — историческая документация релиза. Для текущего использования начните с [Начала работы](../getting-started.md) или [индекса документации](../README.md).

## Главное

### Более спокойный и честный task-first TUI

Обычная навигация больше не расходует дефицитные строки терминала на избыточные status-сообщения вроде opened/selected/action-menu. Текущее положение передают breadcrumb, видимый focus marker и одна контекстная подсказка клавиатуры; status-текст остаётся для обратной связи, способной изменить следующий шаг пользователя.

Empty/dependency states теперь предлагают только реально доступные действия. В частности:

- Providers не предлагает добавить установленный провайдер, если discoverable package отсутствует;
- Rent server может сразу открыть Providers, когда acquisition ещё не настроен;
- Connections может сразу открыть Rent a server, если сервера ещё нет.

Обычная клавиатурная модель остаётся прежней: стрелки + `Enter` + `Esc`. Удалены legacy route-specific буквенные/цифровые пути, дублировавшие видимые Actions; сохранённый refresh accelerator разрешается через ту же semantic availability, что и видимое действие.

### Provider-owned interactive flows стали доступнее

Общий provider choice picker теперь сохраняет полный линейный список вариантов в screen-reader mode и корректно учитывает длинные/переносимые labels внутри визуального viewport терминала. Generic renderer остаётся независимым от предметной области провайдера и одинаково ведёт себя на квалифицированных размерах терминала.

### Единый визуальный язык

Core screens, contextual actions, operation drawers и provider-owned guided flows теперь используют один сдержанный semantic appearance contract:

- единая роль accent/focus;
- muted secondary information;
- стабильные роли success, warning, danger и degraded;
- явные текстовые/focus-маркеры, поэтому цвет никогда не является единственным носителем смысла.

Guided provider workflows больше не проваливаются в отдельно выглядящую monochrome-поверхность, когда окружающий EasyServer TUI работает с цветом.

### Resource views легче сканировать

Servers, Connections, Providers и generic provider tables теперь используют responsive terminal-aware layout вместо длинных строк, построенных вокруг разделителей.

На узкой ширине в первую очередь сохраняются ключевые identity/state данные. На более широких терминалах state и secondary fields получают стабильные колонки, а основная рабочая область ограничивается удобной шириной чтения вместо растягивания текста на весь экран.

Релиз по-прежнему квалифицирован для `60x20`, `80x24` и `120x40`.

### Ограниченная настройка Appearance

Откройте **Settings & Support → Appearance**, чтобы выбрать:

- accent: Cyan (по умолчанию), Blue, Magenta или White;
- density: Comfortable (по умолчанию) или Compact;
- **Reset to defaults**.

Accent влияет только на фирменное/focus-выделение; semantic success, warning и danger остаются неизменными. Compact density уменьшает необязательные вертикальные отступы, не скрывая предупреждения, подтверждения, recovery actions или техническую информацию.

Настройки сохраняются в `~/.easyserver/appearance.json` отдельно от Local State EasyServer. Некорректные или повреждённые appearance-данные безопасно возвращают Cyan + Comfortable. `NO_COLOR` остаётся абсолютным runtime override, а screen-reader output не зависит от оформления.

### Восстановление подключений больше не зависит от английского текста ошибки

Ошибки подключения теперь несут небольшую внутреннюю typed cause: например, отказ SSH authentication, mismatch доверенного host, невозможность получить fingerprint, неготовность SSH, запрет forwarding, недоступность удалённого сервиса, конфликт локального bind или неожиданное завершение transport.

Late foreground failures и ошибки сохранённых фоновых подключений сохраняют безопасную machine-readable cause после завершения исходной async-операции. Решения Retry/Edit/Review trust принимаются по typed cause, а не по regex-сопоставлению человеческого текста ошибки, поэтому изменение формулировки больше не может незаметно изменить recovery behavior.

Raw OpenSSH stderr, учётные данные и небезопасный provider-controlled text по-прежнему не сохраняются для TUI recovery.

### Усилены code-health и test gates

Frontend TUI разделён на task-owned presentation-модули Servers, Connections, Providers/Rent и Diagnostics с общими semantic action builders. Монолитный integration test TUI разделён по behavior domains с сохранением тех же сценариев и общих fixtures.

Workspace-local тесты теперь сначала собирают текущий source и только затем запускают compiled tests, исключая ложные успехи на устаревшем игнорируемом `dist`. Проверки TypeScript на unused locals/parameters включены в compiler gate.

First-party клиенты Vast.ai и Intelion.cloud теперь используют одну canonical bounded/sanitized реализацию безопасной обработки provider errors на build-time. Provider-specific parsing остаётся внутри соответствующего plugin, а опубликованные plugin packages остаются самодостаточными и сохраняют существующий диапазон совместимости SDK `^0.2.0`.

## Набор пакетов и совместимость

В релиз входят:

- `@easyai101/easyserver-plugin-sdk@0.2.3`;
- `@easyai101/easyserver@0.2.3`;
- `@easyai101/easyserver-plugin-vastai@0.2.3`;
- `@easyai101/easyserver-plugin-intelion@0.2.3`.

Compatibility ranges пакетов и Provider Plugins намеренно остаются `^0.2.0`. Благодаря этому `0.2.3` остаётся внутри существующей линии совместимости `0.2.x` и не заставляет обновлять плагины или конфигурацию только из-за patch-релиза.

Корректный Local State `0.2.x` остаётся поддерживаемым; миграции состояния в этом релизе нет.

## Установка этой исторической версии

### npm

```text
npm install --global @easyai101/easyserver@0.2.3
npm install --global @easyai101/easyserver-plugin-vastai@0.2.3
# или
npm install --global @easyai101/easyserver-plugin-intelion@0.2.3
```

### GitHub Release

Release `v0.2.3` публикует:

```text
easyserver-0.2.3-windows-x64.zip
easyserver-0.2.3-linux-x64.tar.gz
easyserver-0.2.3-macos-arm64.tar.gz
easyserver-0.2.3-SHA256SUMS.txt
```

Перед распаковкой проверьте соответствующую контрольную сумму. Точные команды для каждой платформы приведены в разделе [Установка из GitHub Releases](../github-release-install.md).

## Среда релиза

Квалифицированный runtime этого релиза:

- Node.js `24.18.1`;
- npm `11.16.0` для установки npm-пакетов и Provider Plugins.

Квалифицированные client targets:

- Windows 11 x64 с Windows Credential Manager и Windows OpenSSH Client;
- Ubuntu 24.04 x64 с рабочим Linux Secret Store path и системным OpenSSH;
- macOS 15 arm64 с macOS Keychain и системным OpenSSH.

Portable release contract не изменился с `0.2.2`: каждая квалифицированная платформа должна собрать и проверить собственный native artifact до публикации, все native jobs обязаны завершиться успешно, один SHA-256 manifest должен покрывать полный набор артефактов, а post-publication jobs проверяют реальные публичные загрузки.
