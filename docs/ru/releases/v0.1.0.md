# EasyServer 0.1.0

**Язык:** [English](../../releases/v0.1.0.md) · Русский

Релиз: **2026-08-10**

EasyServer `0.1.0` был первым публичным релизом: независимым от провайдера CLI для аренды, управления и локального доступа к удалённым вычислительным ресурсам, при этом специфичная для провайдера логика аренды оставалась в отдельно устанавливаемых Provider Plugins.

Эта страница — историческая документация релиза. Для текущего использования EasyServer обращайтесь к [индексу документации](../README.md).

## Основные возможности

- First-party Provider Plugins для **Vast.ai** и **Intelion.cloud**.
- Общий server inventory и нормализованные lifecycle operations для разных провайдеров.
- Универсальные локальные TCP Endpoints поверх SSH-backed доступа провайдера.
- Foreground connections и persistent Connection Sessions, которыми владел daemon.
- Явное доверие SSH host key при первом использовании; изменение уже доверенного key приводило к fail-closed отказу.
- Credentials провайдера хранились через OS-backed Secret Store, а не в сыром Local State.
- Публичный пакет `@easyai101/easyserver-plugin-sdk` для сторонних Provider Plugins.
- Минимальная установка core с **нулём Provider Plugins, встроенных по умолчанию**.

## Распространение

### npm

Набор пакетов `0.1.0` был опубликован как:

```text
@easyai101/easyserver@0.1.0
@easyai101/easyserver-plugin-sdk@0.1.0
@easyai101/easyserver-plugin-vastai@0.1.0
@easyai101/easyserver-plugin-intelion@0.1.0
```

Provider Plugins были отдельно устанавливаемыми opt-in packages, а не транзитивными зависимостями CLI.

### GitHub Release

Релиз `v0.1.0` публиковал:

```text
easyserver-0.1.0-windows-x64.zip
easyserver-0.1.0-SHA256SUMS.txt
```

Portable ZIP содержал core CLI/runtime dependencies, но не включал Node.js или Provider Plugins.

## Окружение релиза

Поддерживаемой client target для `0.1.0` была **Windows 11 x64** с:

- Node.js `24.18.1`;
- npm `11.16.0` для npm/package installation;
- Windows OpenSSH Client для SSH-backed доступа.

Linux и macOS не входили в контракт поддержки релиза `0.1.0`.

## Важные ограничения 0.1.0

- EasyServer управлял compute/access, но не установкой или оркестрацией workloads.
- Локальный доступ представлял собой raw TCP forwarding, а не HTTP path routing, VPN или application proxying.
- Биллинг провайдера оставался provider-specific; остановленный compute не означал универсально, что биллинг завершён.
- Provider Plugins выполнялись как доверенный in-process code, а не как sandboxed extensions.
- Для SSH-доступа Vast.ai требовалось, чтобы приватный identity, соответствующий публичному ключу аккаунта, был доступен через стандартный OpenSSH identity file или `ssh-agent`; managed path EasyServer не использовал пользовательский `~/.ssh/config` как источник identity.
