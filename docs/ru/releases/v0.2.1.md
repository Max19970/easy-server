# EasyServer 0.2.1

Дата версии: **2026-08-17**

EasyServer `0.2.1` — обратно совместимый maintenance release линии `0.2.x`. Он расширяет список квалифицированных клиентских платформ до Ubuntu 24.04 x64 и macOS 15 arm64, делает обработку сбоев OpenSSH на Unix устойчивее, исправляет нормальный edge case после удаления инстанса Vast.ai и улучшает публичную документацию и публикацию release notes.

Миграция с `0.2.0` не требуется. Существующие валидные `0.2.x` Local State, Secret References, CLI workflows и Provider Plugins, объявляющие совместимость `^0.2.0`, остаются валидными.

Эта страница — историческая документация релиза. Для текущего использования начните с [Начала работы](../getting-started.md) или [индекса документации](../README.md).

## Главное

### Ubuntu 24.04 x64 и macOS 15 arm64 теперь квалифицированы

Начиная с `0.2.1`, матрица поддерживаемых client platforms включает:

- Windows 11 x64;
- Ubuntu 24.04 x64;
- macOS 15 arm64.

Новые release gates для Ubuntu и macOS непрерывно проверяют полный test suite, публикуемую package surface, чистую packaged/global установку Provider Plugins, реальный create/read/delete round trip через системный keyring и требования системных OpenSSH/`ssh-keyscan`.

В ходе Unix-квалификации также были удалены платформозависимые timing assumptions из regression tests для connections и state lock, чтобы release gate проверял поведение, а не скорость планировщика ОС.

Точные требования к ОС, архитектуре, runtime, Secret Store, OpenSSH и headless Linux описаны в [Поддерживаемых платформах](../supported-platforms.md). Portable GitHub Release ZIP остаётся Windows x64-only; Ubuntu и macOS используют установку через npm.

### Более безопасная обработка сбоев OpenSSH на Unix

Гонки при завершении OpenSSH process и его pipes больше не должны показывать пользователю сырые Node.js transport errors вроде `EPIPE` или `ERR_STREAM_PREMATURE_CLOSE`.

EasyServer теперь отделяет публичную writable stream от stdin дочернего процесса, внутренне фиксирует ошибки stdin и после завершения OpenSSH сообщает существующую нормализованную ошибку подключения EasyServer. Regression coverage включает большую запись, находящуюся in-flight во время аварийного завершения процесса.

Семантика явного закрытия и отмены соединения не изменилась.

### Vast.ai после destroy больше не превращает отсутствие инстанса в malformed data

Сразу после успешного destroy Vast.ai может вернуть инстанс как `null` или пустой список. EasyServer теперь трактует эти формы отсутствующего инстанса как нормальное отсутствие вместо вводящей в заблуждение plugin failure `Vast.ai instance must be an object`.

Malformed непустые payloads по-прежнему обрабатываются fail-closed.

### Ссылки в release notes теперь корректны на GitHub Releases

Исходные release notes по-прежнему могут использовать удобные относительные ссылки на документацию репозитория. При tag-driven публикации GitHub Release EasyServer теперь разбирает Markdown и переписывает только реальные относительные destinations у links/images/definitions в URL, закреплённые за точным release commit.

Anchors и внешние URLs сохраняют исходный смысл, repository traversal отклоняется, а несвязанный Markdown остаётся без изменений. Проверка release tag и целостности assets не ослаблена.

### Перестройка публичной документации и русская локализация

Публичная документация была реорганизована вокруг пользовательских задач и долговечных контрактов: установка, connections, background connections, создание и reference Provider Plugins, security, package lifecycle, compatibility и platform support получили более ясные точки входа.

Под `docs/ru/` создана структурированная русская локализация публичной документации, дополненная русскими repository-level README, contributing и security guidance. Английский остаётся каноническим языком контрактов; правила локализации зафиксированы отдельно.

### Небольшое исправление CLI help

Пример `sessions close` теперь использует валидный чистый Session ID вместо некорректной формы placeholder `session:<uuid>`.

## Набор пакетов и совместимость

В релиз входят:

- `@easyai101/easyserver-plugin-sdk@0.2.1`;
- `@easyai101/easyserver@0.2.1`;
- `@easyai101/easyserver-plugin-vastai@0.2.1`;
- `@easyai101/easyserver-plugin-intelion@0.2.1`.

Package и Provider Plugin compatibility ranges намеренно остаются на `^0.2.0`. Таким образом, `0.2.1` остаётся внутри существующей линии совместимости `0.2.x` и не требует обновлять плагины или конфигурацию только из-за patch-релиза.

Валидный Local State из `0.2.0` продолжает поддерживаться; state migration в этом релизе отсутствует.

## Установка этой исторической версии

### npm

```text
npm install --global @easyai101/easyserver@0.2.1
npm install --global @easyai101/easyserver-plugin-vastai@0.2.1
# или
npm install --global @easyai101/easyserver-plugin-intelion@0.2.1
```

### GitHub Release

Release `v0.2.1` публикует portable artifacts для Windows x64:

```text
easyserver-0.2.1-windows-x64.zip
easyserver-0.2.1-SHA256SUMS.txt
```

Portable bundle содержит core CLI/runtime dependencies, но не Node.js и не Provider Plugins.

## Окружение релиза

Квалифицированный runtime этого релиза:

- Node.js `24.18.1`;
- npm `11.16.0` для npm/package installation.

Квалифицированные client targets:

- Windows 11 x64 с Windows Credential Manager и Windows OpenSSH Client;
- Ubuntu 24.04 x64 с рабочим Linux Secret Store path и системным OpenSSH;
- macOS 15 arm64 с macOS Keychain и системным OpenSSH.

На Linux keyring integration сначала пытается использовать D-Bus Secret Service, а если он недоступен — переходит на Linux kernel keyring через keyutils. Границы headless и неквалифицированных окружений описаны в [Поддерживаемых платформах](../supported-platforms.md).
