# EasyServer 0.2.0

**Язык:** [English](../../releases/v0.2.0.md) · Русский

Релиз: **2026-08-16**

EasyServer `0.2.0` сделал интерактивный TUI предпочтительной human-facing точкой входа, сохранив CLI как явную поверхность для автоматизации и продвинутых команд.

Он также перевёл Provider Plugin SDK и оба first-party plugin на линию совместимости `0.2.x`, расширил публичные контракты взаимодействия с провайдерами/help и усилил восстановление подключений и SSH trust после реальной приёмки на провайдерах.

Эта страница — историческая документация релиза. Для текущего использования начните с [Начала работы](../getting-started.md) или [индекса документации](../README.md).

## Основные возможности

### Интерактивный TUI, ориентированный на задачи

Обычный `easyserver` открывает TUI в интерактивном terminal. Основной пользовательский путь организован вокруг:

- **Rent a server**;
- **Servers**;
- **Connections**;
- **Settings & Support**.

Рабочие страницы используют сфокусированный breadcrumb layout, контекстные Actions и единую модель взаимодействия arrows/Enter/Esc вместо показа внутренних подсистем как равноправных вкладок.

Установленные Provider Plugins, которые объявляют package metadata EasyServer, можно выбирать по понятному человеку display name без импорта ненастроенного provider runtime только ради заполнения picker.

Provider-specific acquisition остаётся во владении провайдера: Vast.ai сохраняет модель marketplace/filter/rental, а Intelion.cloud — модель server catalog/configurator.

### Более удобные подключения к серверам

Обычный Connect flow запрашивает удалённый **application/service port**, а не SSH transport port, и может автоматически выбрать объявленный провайдером connection method.

Connections показывает локальные адреса, не требуя от пользователя заранее понимать внутренние сущности Access Method, Session, daemon или saved intent.

Восстановление стало зависящим от конкретной причины и выполняется на месте:

- конфликт локального порта → изменить local port;
- SSH работает, но service port недоступен → изменить service port;
- retryable late transport/auth failure → повторить сохранённый connection request;
- first-use SSH trust → проверить точное fingerprint evidence;
- сохранённое background connection ждёт trust → проверить fingerprint и повторить ту же saved definition.

Сообщения SSH connection разделяют provider API authentication, SSH login authentication, изменение host identity, сбой обнаружения fingerprint, SSH transport failure, server-side TCP-forwarding policy и доступность remote application/service.

Если `ssh-keyscan` не может получить first-use host-key evidence, EasyServer может выполнить ограниченный изолированный OpenSSH handshake только для наблюдения. Permanent trust всё равно требует явного подтверждения и свежей точной перепроверки.

### Diagnostics и ограниченные terminals

Diagnostics теперь начинается с краткой сводки и предоставляет отдельный scrollable report viewer. Copy использует тот же sanitised payload, который пользователь просматривает, а screen-reader mode получает полный отчёт линейно.

TUI поддерживает узкие terminals, `NO_COLOR` и Ink screen-reader mode, сохраняя доступность сфокусированного/actionable содержимого.

### Машиночитаемый контракт CLI

Автоматизация может добавить префикс `--json` перед именованной командой и получить envelope schema version `1`.

Успешные команды выводят один документ `{ schemaVersion, ok: true, data }` в stdout. Terminal failures выводят один документ `{ schemaVersion, ok: false, error }` в stderr с ненулевым exit status.

First-use SSH trust может предоставлять структурированное свидетельство host/key. Отдельная команда `host-trust approve` авторизует ровно это свидетельство после перепроверки, позволяя неинтерактивной автоматизации оставаться fail-closed.

Текущий контракт `0.2.x` описан в [Машиночитаемом выводе CLI](../cli-json.md).

### Provider Plugin SDK 0.2.x

SDK `0.2.0` добавил публичные контракты, необходимые TUI и host-owned safety model, включая:

- declarative credential descriptors/readiness metadata;
- metadata риска `billable`/`destructive` для provider mutations;
- structured provider command help и отдельный side-effect-free contribution `./easyserver-help`;
- контракты provider command result/handoff для затронутых provider identities;
- presentation-neutral интерактивные flows провайдера;
- более строгую семантику provider identity/deletion для неубедительных observations.

Provider-specific configuration/acquisition по-прежнему относится к Provider Features, а не к EasyServer core.

## Изменения совместимости относительно 0.1.x

### Обычный `easyserver`

Намеренное изменение пользовательской точки входа:

- `0.1.x`: обычный `easyserver` мог восприниматься как вызов command mode;
- `0.2.0`: обычный `easyserver` открывает TUI в поддерживаемом интерактивном terminal.

Скрипты, которым нужна справка, должны использовать:

```powershell
easyserver --help
```

Именованные команды `plugins`, `instances`, `connect`, `daemon` и `sessions` остаются command-mode paths.

Вызов без аргументов в неинтерактивном режиме завершается понятной ошибкой вместо вывода terminal-control sequences.

### Линия совместимости плагинов

Опубликованный набор пакетов:

- `@easyai101/easyserver-plugin-sdk@0.2.0`;
- `@easyai101/easyserver@0.2.0`;
- `@easyai101/easyserver-plugin-vastai@0.2.0`;
- `@easyai101/easyserver-plugin-intelion@0.2.0`.

First-party packages/manifests используют линию совместимости `^0.2.0`. Plugin, объявляющий только `^0.1.0`, не заявляет совместимость с host/SDK `0.2.x`.

### Local State и credentials

`0.2.0` не требовал удаления/пересоздания валидного EasyServer Local State. Валидный state `0.1.x` остаётся читаемым, canonical instance identity сохраняется, а opaque Secret References продолжают адресовать OS-backed credentials.

Линия `0.2.x` также добавила проверяемое поведение recovery generation Local State и crash-recoverable ownership metadata для вновь создаваемого временного SSH credential material на квалифицированном Windows path.

## Установка этой исторической версии

### npm

```powershell
npm install --global @easyai101/easyserver@0.2.0
npm install --global @easyai101/easyserver-plugin-vastai@0.2.0
# or
npm install --global @easyai101/easyserver-plugin-intelion@0.2.0
```

### GitHub Release

Релиз `v0.2.0` публиковал:

```text
easyserver-0.2.0-windows-x64.zip
easyserver-0.2.0-SHA256SUMS.txt
```

Portable bundle содержит core CLI/runtime dependencies, но не Node.js или Provider Plugins.

## Окружение релиза

Поддерживаемой client target для `0.2.0` была:

- Windows 11 x64;
- Node.js `24.18.1`;
- npm `11.16.0` для npm/package installation;
- Windows OpenSSH Client для SSH-backed доступа.

Linux и macOS не входили в контракт поддержки релиза `0.2.0`.
