# Аудит зависимостей и цепочки поставки EasyServer 0.1.0

**Язык:** [English](../../releases/v0.1.0-dependency-audit.md) · Русский

Дата аудита: 2026-08-10.

Этот отчёт фиксирует production dependency surface, проверенную для первого публичного релиза `0.1.0`. Это снимок на момент релиза, а не обещание, что advisories в registry никогда не изменятся после публикации.

## Production dependency surface

`@easyai101/easyserver-plugin-sdk` не имеет внешней executable runtime dependency. Он устанавливает `@types/node@24.13.3` (и его declaration dependency `undici-types`), потому что публичный контракт Access Channel намеренно предоставляет точный тип Node `Duplex`. Эти пакеты содержат только declarations и не выполняются EasyServer во время runtime.

`@easyai101/easyserver-plugin-vastai` и `@easyai101/easyserver-plugin-intelion` зависят только от `@easyai101/easyserver-plugin-sdk`. Это отдельно устанавливаемые Provider Plugins, и они не являются зависимостями `@easyai101/easyserver`.

У `@easyai101/easyserver` ровно три прямые runtime dependencies:

| Зависимость | Диапазон/версия 0.1.0 | Причина использования в runtime | Лицензия |
| --- | --- | --- | --- |
| `@easyai101/easyserver-plugin-sdk` | `^0.1.0` | Публичные/runtime контракты Provider Plugin, validation, normalized errors и operation types | MIT |
| `@napi-rs/keyring` | `1.3.0` | OS-backed Secret Store, используемый для хранения credentials вне Local State | MIT |
| `semver` | `7.7.2` | Runtime validation диапазонов совместимости EasyServer/Plugin SDK у Provider Plugin | ISC |

Установленные с SDK declaration packages Node (`@types/node@24.13.3` и `undici-types@7.18.0`) также имеют лицензию MIT. Лицензии ISC и MIT разрешительные и совместимы с распространением самого EasyServer под MIT. В production closure, проверенной для `0.1.0`, не было зависимостей с copyleft или source-availability лицензиями.

## Native dependency

`@napi-rs/keyring@1.3.0` — единственная native runtime dependency. JavaScript wrapper выбирает platform-specific optional package с prebuilt native `.node` binary.

Для поддерживаемого release path Windows 11 x64 npm устанавливает `@napi-rs/keyring-win32-x64-msvc@1.3.0`. Проверенный установленный пакет содержит package metadata/README и один prebuilt native module (`keyring.win32-x64-msvc.node`, примерно 1.8 MB).

Keyring wrapper и все platform-specific optional packages, зафиксированные в `package-lock.json`, лицензированы по MIT. Ни у одной из этих lockfile entries нет npm install script. В частности, поддерживаемый Windows package не компилирует native code и не запускает download/build script во время установки EasyServer; npm выбирает prebuilt package по OS/CPU metadata.

EasyServer отдельно проверил реальный цикл create/read/delete через OS keyring на поддерживаемой Windows platform. Поэтому поддержка платформы не выводилась только из факта существования native packages; текущая platform policy описана в [Поддерживаемых платформах](../supported-platforms.md).

## Install-time scripts

В проверенном `package-lock.json` нет dependency entry с `hasInstallScript`. Собственные publishable packages EasyServer используют build/prepack lifecycle scripts при создании release artifacts, но опубликованные runtime tarballs уже содержат собранный `dist/` output и не зависят от consumer-side postinstall installer.

Корень репозитория намеренно не публикуется и имеет аварийно завершающийся guard `prepublishOnly` вдобавок к `private: true`. Это предотвращает случайную публикацию корня монорепозитория, хотя npm всё ещё способен собрать dry-run payload для private package.

## Целостность registry и advisories

С release-версией npm (`11.16.0`) на locked tree по состоянию на 2026-08-10:

```text
npm audit --omit=dev --audit-level=low
→ found 0 vulnerabilities

npm audit signatures --omit=dev
→ 5 packages have verified registry signatures
→ 4 packages have verified attestations
```

Registry tarballs для проверенных внешних runtime dependencies закреплены integrity hashes в `package-lock.json`. Для детерминированной установки repository/CI используется `npm ci`, а не неявное обновление lockfile.

На этом checkpoint не осталось известных npm advisories уровня high/critical или меньшей серьёзности, затрагивающих проверенное production tree.

## Publishable tarballs EasyServer

Release gate выполняет реальную проверку `npm pack` для каждого publishable EasyServer package. Он отклоняет неожиданные paths и требует, чтобы artifact каждого пакета содержал только:

```text
LICENSE
README.md
package.json
dist/**
```

Внешний minimal Provider Plugin example имеет собственный точный scaffold allowlist.

Тот же packaged-install test создаёт изолированные global npm prefixes вне монорепозитория, устанавливает packed CLI/SDK, запускает фактический созданный npm executable `easyserver` и проверяет явную регистрацию Provider Plugin. Он также создаёт отдельный TypeScript consumer project во временной директории, устанавливает только packed SDK как зависимость EasyServer, компилирует provider и Access Adapter на основе Node `Duplex` через package-root declarations и запускает сгенерированный module.

## Граница минимальной установки

В packed-установке `@easyai101/easyserver` отсутствуют пакеты Vast.ai и Intelion.cloud и нет настроенных Provider Plugins. Затем проверка независимо устанавливает по одному Provider Plugin и доказывает отсутствие несвязанного Provider Plugin.

Это исполняемый release contract, а не только проверка manifest. Он защищает модель, в которой Provider Plugins являются опциональным выбором пользователя, а не транзитивными зависимостями CLI.

## Команды release audit

Release snapshot проверялся командами:

```sh
npm ls --omit=dev --all
npm audit --omit=dev --audit-level=low
npm audit signatures --omit=dev
npm run verify:packaged-install
npm run verify:os-keyring
npm run release:check
```

Команды advisory/signature зависели от registry и намеренно были отделены от детерминированного test gate. Значения выше фиксируют checkpoint release audit от 2026-08-10; они не являются заявлениями о состоянии registry после этой даты.

## Результат

Production dependency surface `0.1.0` невелика и обоснована, поддерживаемый native dependency path понятен, dependency install scripts не требуются, лицензии зависимостей совместимы с распространением по MIT, в проверенном registry tree не было известных уязвимостей, а packaged-install verification сохраняет контракт с нулём встроенных Provider Plugins.
