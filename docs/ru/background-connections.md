# Фоновые подключения

**Язык:** [English](../background-connections.md) · Русский

Используйте daemon EasyServer, когда локальное подключение должно пережить терминал/TUI, в котором оно было создано, или управляться как фоновое состояние.

Здесь есть два связанных понятия:

- **Session** — одно живое подключение под управлением daemon в течение текущего времени жизни daemon;
- **сохранённое подключение** (Endpoint intent в терминологии CLI) — желаемое состояние, которое daemon может снова реализовать после перезапуска.

Если подключение нужно только на время выполнения одной команды, используйте [foreground `connect`](connections.md).

## Запуск управляемого daemon

Для обычной работы на desktop и автоматизации:

```powershell
easyserver daemon start
```

Проверить состояние:

```powershell
easyserver daemon status
```

`daemon start` идемпотентна, если аутентифицированный daemon уже исправно работает. Перед запуском нового управляемого процесса команда также обрабатывает устаревший descriptor.

Foreground-режим используйте только для отладки или когда процессом daemon должен владеть другой process manager:

```powershell
easyserver daemon run
```

Эта команда остаётся в текущем терминале. Для обычной desktop-работы это не предпочтительный путь.

Остановить управляемый daemon:

```powershell
easyserver daemon stop
```

Остановка daemon закрывает живые локальные transport-подключения. Она **не** уничтожает вычислительные ресурсы. Сохранённые определения подключений остаются в Local State и могут быть снова реализованы при следующем запуске daemon.

## Создание фоновой Session

При работающем daemon:

```powershell
easyserver sessions create <instance-id> --port 8188
```

Те же параметры подключения, что используются foreground `connect`, доступны там, где это применимо:

```powershell
easyserver sessions create <instance-id> `
  --port 8188 `
  --local-port 54321 `
  --access-method <method-id>
```

Список текущих Sessions:

```powershell
easyserver sessions list
```

Явно закрыть одну Session:

```powershell
easyserver sessions close <session-id>
```

Неудачная Session сохраняет ограниченную запись о сбое, чтобы очистка/восстановление оставались видимыми. Закрытие такой Session повторяет очистку и удаляет запись, когда очистка успешно завершится.

## Идемпотентное создание Session

Автоматизация может передать стабильный idempotency key:

```powershell
easyserver sessions create <instance-id> `
  --port 8188 `
  --idempotency-key comfyui-main
```

Повтор того же ключа с тем же запросом подключения переиспользует ту же живую Session вместо открытия дубликата. Повторное использование ключа с другими настройками завершается конфликтом.

Идемпотентность Session локальна для daemon. Закрытие Session освобождает ключ, а перезапуск daemon не сохраняет идентичность живой Session.

## Сохранение подключения между перезапусками daemon

Сохраните желаемое состояние подключения как именованный Endpoint intent:

```powershell
easyserver sessions intents create comfyui-main <instance-id> `
  --port 8188 `
  --local-port 54321
```

Посмотреть сохранённые определения и текущее состояние их реализации:

```powershell
easyserver sessions intents list
```

Сохранённое определение может находиться в состоянии `starting`, `live`, `error` или `disabled`. Local State хранит желаемые настройки instance/target/local-port/method и признак включённости определения; он не сохраняет старую живую Session и не делает вид, что старый transport пережил перезапуск.

При запуске daemon включённые определения реализуются заново на основе текущего состояния провайдера. Ошибка одного определения не мешает запуску исправных соседних определений.

## Восстановление одного неудачного сохранённого подключения

После устранения причины — например проблем с учётными данными, SSH trust, доступностью провайдера, готовностью сервиса или конфликтом локального порта — повторите только это сохранённое определение:

```powershell
easyserver sessions intents retry comfyui-main
```

Если мешает SSH trust при первом использовании, TUI может показать **Review SSH fingerprint** для этого сохранённого подключения, добавить проверенный ключ через тот же усиленный trust-путь и повторить ту же конфигурацию.

Для неинтерактивной автоматизации `--json` предоставляет структурированные данные host trust. См. [Машиночитаемый вывод CLI](cli-json.md#явное-доверие-ssh-host-для-автоматизации).

## Отключение, включение или удаление сохранённого состояния

Временно остановить реализацию, не удаляя определение:

```powershell
easyserver sessions intents disable comfyui-main
easyserver sessions intents enable comfyui-main
```

Полностью удалить желаемое определение:

```powershell
easyserver sessions intents remove comfyui-main
```

Disable/remove закрывает только локальный transport этого определения. Сервер провайдера не останавливается и не уничтожается.

## Изменения конфигурации при работающем daemon

Работающий daemon перезагружает состояние включения плагинов провайдеров и привязки учётных данных для **новой** настройки подключений. Поэтому добавление/включение/отключение плагина или смена/удаление учётных данных не требует перезапуска daemon только ради влияния на будущие подключения.

Уже принятое подключение сохраняет свой runtime и не разрывается лишь потому, что конфигурация впоследствии изменилась. Если текущая конфигурация провайдера не поддерживает новую настройку, новая попытка завершается явной ошибкой, а уже работающие исправные Sessions могут продолжать работу.

## Использование SSH или SCP через локальный Endpoint

EasyServer пересылает сырой TCP. Поэтому можно опубликовать собственный SSH-сервис сервера, а затем запустить отдельный SSH/SCP-клиент через локальный listener.

Создайте фоновое подключение к удалённому порту 22:

```powershell
easyserver sessions create <instance-id> --host 127.0.0.1 --port 22
```

Допустим, EasyServer сообщил `127.0.0.1:54322`. Второй SSH-клиент может использовать:

```powershell
ssh -p 54322 root@127.0.0.1
```

или:

```powershell
scp -P 54322 .\model.safetensors root@127.0.0.1:/root/
```

Этот *внутренний* SSH/SCP-процесс сам отвечает за свои authentication и host trust. EasyServer лишь пересылает TCP-байты через уже установленный путь подключения провайдера.

## Уничтожение сервера с фоновыми подключениями

Уничтожение ресурса провайдера и очистка локальных подключений — разные операции.

По умолчанию `instances destroy` отказывается продолжать, если у цели остаются Sessions daemon или включённые сохранённые определения подключений. Когда вы намеренно хотите, чтобы EasyServer сначала закрыл эти локальные подключения и только затем отправил провайдеру команду уничтожения, используйте координируемую host-стороной опцию, описанную командой:

```powershell
easyserver instances destroy <instance-id> --close-sessions --yes
```

EasyServer отключает связанные сохранённые определения и закрывает Sessions daemon до отправки удалённой операции destroy. Если локальная очистка не удалась, уничтожение у провайдера не выполняется.

Если цель — прекратить оплату ресурса, всегда следуйте правилам очистки в руководстве провайдера:

- [Vast.ai](providers/vastai.md)
- [Intelion.cloud](providers/intelion.md)
