# Подключение к удалённому сервису

**Язык:** [English](../connections.md) · Русский

EasyServer может сделать TCP-сервис, работающий на управляемом сервере, доступным через локальный адрес на вашем компьютере.

```text
server:127.0.0.1:8188  →  EasyServer  →  127.0.0.1:54321
```

Обычный сценарий TUI скрывает детали транспорта, пока они не понадобятся. В этом руководстве описаны модель подключения, CLI-эквиваленты, SSH trust при первом использовании и основные способы восстановления.

## Откройте подключение в текущем процессе

В TUI откройте **Servers**, выберите новый сервер и нажмите **Connect**. Укажите порт приложения/сервиса, работающего на этом сервере.

Эквивалент в CLI:

```powershell
easyserver connect <instance-id> --port 8188
```

После успеха EasyServer выводит локальный адрес, например:

```text
127.0.0.1:54321
```

Команда `connect` владеет этим локальным подключением до своего завершения. Когда закончите, нажмите `Ctrl+C`.

## Удалённый порт и локальный порт

`--port` — TCP-порт **на удалённой цели**. Если ваша рабочая нагрузка слушает на арендованном сервере `127.0.0.1:8188`, используйте:

```powershell
easyserver connect <instance-id> --port 8188
```

Удалённый target host по умолчанию — `127.0.0.1`. Продвинутые сценарии могут его изменить:

```powershell
easyserver connect <instance-id> --host 127.0.0.1 --port 8188
```

Локальный listener всегда доступен только через loopback-интерфейс. По умолчанию EasyServer динамически выбирает свободный локальный порт.

Запросите постоянный локальный порт, если другому локальному инструменту нужен фиксированный адрес:

```powershell
easyserver connect <instance-id> --port 8188 --local-port 54321
```

Если этот локальный порт занят, EasyServer сообщает о конфликте, а не молча выбирает другой.

## Доверие SSH host при первом использовании

Методы подключения через SSH требуют явного доверия к host.

Когда EasyServer впервые видит host, интерактивный сценарий показывает:

- SSH host и port;
- тип host key;
- SHA-256 fingerprint.

Экран доверия по умолчанию установлен на **Decline**. При выборе **Trust** EasyServer добавляет только просмотренный ключ и только после повторной проверки, что предъявляется всё тот же предпочтительный ключ.

EasyServer ведёт собственное хранилище SSH trust по адресу `~/.easyserver/known_hosts`. Доверие, подтверждённое отдельной командой `ssh`, автоматически не импортируется.

Изменившийся ключ уже доверенного host приводит к fail-closed ошибке. Не воспринимайте это как новый запрос первого доверия: прежде чем удалять старую доверенную запись, проверьте, действительно ли сервер был заменён или переустановлен.

### Когда `ssh-keyscan` не может получить fingerprint

Обычно EasyServer использует `ssh-keyscan`, чтобы увидеть host key при первом подключении. Если все настроенные scanner-варианты завершаются неудачей, но настроенный клиент OpenSSH всё ещё может выполнить key exchange, EasyServer может провести ограниченный handshake OpenSSH без команд, используя изолированный временный файл `known_hosts`.

Этот fallback только получает данные для проверки. Временный файл удаляется и никогда не становится постоянным доверием. Перед записью в собственное хранилище доверия EasyServer всё равно требует явного подтверждения и новой точной проверки.

Если fingerprint нельзя получить ни одним способом, EasyServer сообщает, что безопасно предложить действие доверия невозможно. Повторите попытку, если сервер ещё может запускаться, и используйте Diagnostics для проверки локальных SSH-инструментов.

## SSH authentication отделена от API authentication провайдера

Учётные данные API провайдера могут быть корректными, даже если SSH login завершается ошибкой.

Например, доступ по SSH в Vast.ai обычно зависит от публичного ключа на уровне аккаунта и соответствующего локального private identity, который OpenSSH может обнаружить. Intelion.cloud может получить пароль конкретного сервера через API после успешной проверки доверия к SSH host.

Поэтому TUI отличает ошибки SSH authentication от ошибок учётных данных провайдера и не предлагает менять рабочий API token/key.

Требования конкретных провайдеров к подключению:

- [Vast.ai](providers/vastai.md#подключение-к-сервису)
- [Intelion.cloud](providers/intelion.md#подключение-к-сервису)

## Методы подключения

Провайдер может объявлять более одного метода TCP-forward подключения. В обычном TUI EasyServer выбирает поддерживаемый метод за вас.

Если нужен контроль над маршрутом, посмотрите доступные методы через CLI:

```powershell
easyserver instances access-methods <instance-id>
```

Явно выбрать один из них можно так:

```powershell
easyserver connect <instance-id> --port 8188 --access-method <method-id>
```

Если запрошенный метод недоступен, EasyServer завершает операцию с ошибкой, а не молча переключается на другой.

Метод подключения на стороне провайдера и локальный адрес — разные понятия: метод описывает, как EasyServer достигает сервера; локальный адрес — это listener на loopback-интерфейсе, который использует ваше приложение.

## Разбор ошибок подключения

Когда это можно сделать безопасно, EasyServer классифицирует уровень, на котором произошёл сбой.

### Fingerprint host недоступен

EasyServer не смог получить данные SSH host key ни через keyscan, ни через изолированный fallback-handshake. Если сервер только что создан, немного подождите и повторите попытку. Если прямой SSH стабильно работает, откройте Diagnostics и проверьте локальные инструменты OpenSSH.

### Host key изменился

Сервер предъявляет ключ, отличный от уже доверенного EasyServer. Это остаётся fail-closed ошибкой. Проверьте идентичность сервера, прежде чем менять состояние доверия.

### SSH authentication отклонена

SSH-маршрут доступен, но учётные данные входа отклонены. Проверьте специфичный для провайдера путь SSH-учётных данных, а не предполагайте, что неверны API-учётные данные провайдера.

### TCP forwarding не разрешён

SSH login выполнен успешно, но SSH-сервер отказал в forwarding channel. Выберите другой поддерживаемый метод подключения, если он есть, либо измените политику SSH forwarding на сервере.

### Порт сервиса отклоняет подключение

SSH работает, но на запрошенном порту приложения/сервиса никто не принимает подключения. Запустите рабочую нагрузку, дождитесь её готовности или используйте **Edit service port**.

### Удалённая цель недоступна или истёк тайм-аут

SSH работает, но запрошенная цель недоступна с сервера. Проверьте bind address рабочей нагрузки, port, firewall/network path и выбранный remote host.

### Конфликт локального порта

Запрошенный `--local-port` уже используется на вашем компьютере. Выберите другой локальный порт или позвольте EasyServer назначить его динамически.

Поздние ошибки остаются видимыми в **Connections**, а не исчезают после первоначальной публикации локального listener. Повтор использует сохранённый запрос; изменение service/local port сохраняет остальные поля.

## Диагностика и приватность

**Settings & Support → Diagnostics** показывает санитизированный отчёт поддержки о текущей готовности EasyServer, провайдера, daemon и SSH-инструментов.

EasyServer не хранит произвольный сырой stderr OpenSSH как обычное состояние TUI, а отчёт Diagnostics не заявляет, что содержит необработанный вывод предыдущей неудачной попытки подключения. Это не позволяет поверхностям поддержки превращаться в дамп секретов или ответов провайдера.

## Нужно, чтобы подключение пережило этот терминал?

`connect` намеренно привязан ко времени жизни текущего процесса/TUI. Для фоновых подключений под управлением daemon и определений, которые можно воссоздать после перезапуска, продолжите с раздела [Фоновые подключения](background-connections.md).
