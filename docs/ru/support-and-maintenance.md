# Поддержка и сопровождение

**Язык:** [English](../support-and-maintenance.md) · Русский

EasyServer — молодой open-source проект, который сопровождается по мере возможностей. На этой странице описано, куда сообщать о проблемах и какого сопровождения пользователям следует ожидать, без создания впечатления о корпоративном контракте поддержки или фиксированном графике релизов.

Гарантии совместимости отдельно определены в документе [Версионирование и совместимость](versioning-and-compatibility.md). Для уязвимостей безопасности используется закрытый процесс, описанный в [SECURITY.ru.md](../../SECURITY.ru.md).

## Сообщение об обычной ошибке

Для воспроизводимых ошибок продукта, проблем удобства использования, регрессий провайдеров и ошибок документации открывайте публичный GitHub issue.

Полезный отчёт включает:

- версию EasyServer;
- Provider Plugin и его версию, если проблема относится к конкретному провайдеру;
- операционную систему и версию Node.js;
- команду или сценарий TUI, в котором произошёл сбой;
- ожидаемый результат и то, что произошло фактически;
- минимальный пример воспроизведения, когда это практично;
- проверенный и очищенный отчёт Diagnostics, если он помогает диагностике.

Для регрессий провайдера укажите затронутого провайдера и сообщите, работал ли тот же сценарий ранее.

Не включайте секреты или приватные данные аккаунта в публичный issue.

## Использование безопасной для публикации Diagnostics

В TUI доступен раздел **Settings & Support → Diagnostics**. В командном режиме также есть:

```powershell
easyserver doctor
```

Отчёт спроектирован так, чтобы предоставлять ограниченную информацию о состоянии продукта и runtime без разрешения credentials провайдера и без выгрузки сырых ответов провайдера.

Он может включать, например:

- версии EasyServer, Node.js, платформы и архитектуры;
- доступность чтения Local State и укрупнённые количества настроенных объектов;
- состояние загрузки/готовности настроенных Provider Plugins и их загруженные версии;
- укрупнённые классы ошибок плагинов;
- состояние daemon и ограниченные количества соединений;
- доступность локальных инструментов OpenSSH.

Из обычного support payload намеренно исключаются необработанные значения credentials и Secret References, приватный SSH-материал, bearer-токены daemon, секреты loopback descriptor, идентификаторы аккаунтов/ресурсов провайдера, локальные пути к файлам плагинов и сырые тела исключений провайдера/плагина.

Тем не менее перед публикацией отчёта просмотрите его, особенно если установлены сторонние Provider Plugins.

## Никогда не публикуйте это в публичном issue

Не публикуйте:

- API keys/tokens;
- passwords;
- private SSH keys;
- bearer/session/daemon authentication tokens;
- необработанные значения credentials;
- Secret References вида `secret:<uuid>`;
- непроверенное содержимое `~/.easyserver`;
- экспорты OS keyring;
- сырые payload провайдера с данными аккаунта/ресурсов;
- непроверенные debug logs.

Если речь идёт о предполагаемой уязвимости, а не об обычной ошибке, остановитесь и используйте закрытый канал сообщения об уязвимостях из [SECURITY.ru.md](../../SECURITY.ru.md).

## Сопровождение текущей линии

Пока `0.2.x` является текущей выпущенной линией совместимости, подтверждённые регрессии в документированном поведении `0.2.x` могут исправляться patch-релизом, если это можно сделать без нарушения публичного контракта этой линии.

Совместимый patch-релиз может включать:

- исправления ошибок и проблем безопасности;
- исправления в ответ на изменения API провайдеров;
- обслуживание зависимостей;
- исправления документации;
- небольшие аддитивные изменения, не меняющие существующие требования.

Изменение, требующее миграции от пользователей, скриптов или совместимых Provider Plugins, обычно относится к следующей minor-линии совместимости.

`0.1.x` больше не получает общего сопровождения, пока текущей является `0.2.x`. Критические исправления безопасности или целостности данных могут быть backport'нуты по усмотрению сопровождающих, но обещания бессрочных backport'ов нет.

## Сопровождение first-party провайдеров

Плагины Vast.ai и Intelion.cloud сопровождаются в той же текущей линии совместимости, что и EasyServer, пока документированные интеграции с провайдерами остаются работоспособными.

API и политики провайдеров — внешние зависимости. Если изменение upstream ломает интеграцию, проект может:

1. выпустить обратно совместимое исправление плагина;
2. задокументировать временное ограничение, пока исправление недоступно;
3. объявить интеграцию устаревшей или удалить её в более поздней линии совместимости, если upstream-контракт перестал быть практичным.

Если сам провайдер удаляет API или сервис, необходимый интеграции, EasyServer не может гарантировать дальнейшую доступность провайдера; затронутый провайдер должен завершаться понятной ошибкой, не повреждая состояние других провайдеров.

## Работа с вопросами безопасности

Закрытые сообщения об уязвимостях расследуются и исправляются по мере возможностей. Совместимое исправление может выйти patch-релизом текущей линии; исправление, нарушающее совместимость, переносится в более позднюю линию, если только сохранение старого поведения не оставляет пользователей в небезопасном состоянии.

Фиксированный SLA по подтверждению или исправлению не обещается. Координируйте раскрытие через закрытое сообщение, а не открывайте публичный issue для ещё не раскрытой уязвимости.

## Чего поддержка не обещает

EasyServer сейчас не предоставляет:

- платного контракта поддержки;
- SLA по времени ответа;
- гарантии uptime или доступности провайдера;
- гарантированного графика релизов;
- бессрочного сопровождения pre-1.0 линий.

Сопровождающие могут расставлять приоритеты по серьёзности, воспроизводимости, влиянию на пользователей, риску безопасности/целостности данных и доступным ресурсам проекта.
