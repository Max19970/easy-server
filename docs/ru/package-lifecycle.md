# Обновление, переустановка и удаление EasyServer

**Язык:** [English](../package-lifecycle.md) · Русский

EasyServer хранит пользовательское состояние и ресурсы провайдеров отдельно от файлов установленных пакетов. Поэтому операции пакетного менеджера меняют локальный код, но не уничтожают удалённые серверы и не сбрасывают поддерживаемое состояние EasyServer.

Правила совместимости для этих операций описаны в разделе [Версионирование и совместимость](versioning-and-compatibility.md).

## Обновление или переустановка в пределах `0.2.x`

Совместимое обновление/переустановка в пределах `0.2.x` сохраняет корректное поддерживаемое состояние той же линии совместимости. EasyServer `0.2.0` также принимает корректный Local State версии `0.1.x`.

При обычной конфигурации:

- Local State находится в `~/.easyserver/state.json` (или в пути, заданном `EASYSERVER_STATE_FILE`), вне каталога npm-пакета;
- канонические идентичности instances EasyServer и настроенные регистрации провайдеров остаются в Local State;
- значения учётных данных остаются в Secret Store операционной системы;
- Local State хранит непрозрачные Secret References, а не сырые значения учётных данных;
- переустановка пакета не является сбросом состояния.

Удаление Local State ради того, чтобы совместимое обновление заработало, не считается допустимой стратегией миграции.

Provider Plugins — отдельные пакеты. Обновление основной CLI не устанавливает, не обновляет и не удаляет их автоматически.

## Если настроенный Provider Plugin отсутствует или несовместим

Зарегистрированный пакет провайдера может временно не загружаться, если он удалён, его модуль сломан или объявленная совместимость с EasyServer/Plugin SDK не принимает установленные версии.

EasyServer рассматривает это как недоступность провайдера, а не как свидетельство исчезновения пользовательских ресурсов или конфигурации провайдера.

- `easyserver plugins list` показывает настроенный плагин как failed с безопасной с точки зрения приватности причиной загрузки/совместимости.
- Другие исправные провайдеры остаются независимо доступными.
- Регистрация плагина, credential Secret References и canonical instance bindings остаются сохранёнными.
- Переустановка совместимого плагина может восстановить ту же настроенную связь.

Не удаляйте состояние и не создавайте ресурсы провайдера заново только потому, что локальный пакет плагина временно недоступен.

## Переустановка одного пакета провайдера

Для глобальной npm-установки переустановите соответствующий совместимый плагин в той же глобальной пакетной среде, где установлен EasyServer:

```powershell
npm install --global @easyai101/easyserver-plugin-vastai@^0.2.0
# or
npm install --global @easyai101/easyserver-plugin-intelion@^0.2.0
```

Для установки из переносимого ZIP устанавливайте провайдера в этот распакованный prefix. См. [Установка из GitHub Releases](github-release-install.md#добавьте-provider-plugin-позже).

Провайдер остаётся настроенным в Local State EasyServer, пока вы явно не удалите его регистрацию.

## Удаление пакетов не очищает ресурсы провайдера

Удаление `@easyai101/easyserver` или Provider Plugin удаляет только установленный код пакета.

EasyServer намеренно не имеет package-manager uninstall hook, который уничтожает ресурсы провайдера, удаляет Local State или записи Secret Store.

В частности:

- удаление основной CLI никогда не отправляет провайдеру операции stop/destroy/release;
- удаление Provider Plugin никогда не уничтожает серверы этого провайдера;
- Local State остаётся доступным для последующей совместимой переустановки;
- учётные данные остаются в Secret Store ОС, пока вы не удалите их явно.

Удалённые вычислительные ресурсы могут продолжать существовать и тарифицироваться даже после удаления локального пакета.

## Удаление учётных данных перед деинсталляцией

Если вы намеренно хотите удалить учётные данные из связи с Secret Store EasyServer, сделайте это, пока CLI ещё установлена:

```powershell
easyserver plugins credential remove @easyai101/easyserver-plugin-vastai api-key
easyserver plugins credential remove @easyai101/easyserver-plugin-intelion api-token
```

Удаление локальных учётных данных всё равно не уничтожает ресурс провайдера.

## Полное удаление

Если вы хотите полностью прекратить использовать EasyServer:

1. Проверьте ресурсы провайдеров, которыми вы всё ещё владеете.
2. Уничтожьте/освободите все платные ресурсы, которые больше не нужны, соблюдая правила биллинга провайдера.
3. Убедитесь, что состояние у провайдера сошлось к нужному конечному/отсутствующему состоянию.
4. Закройте/отключите фоновые подключения, которые больше не нужны.
5. Удалите учётные данные провайдера из EasyServer, если хотите удалить их связь с Secret Store ОС.
6. Удалите пакеты Provider Plugin и основную CLI.
7. Удаляйте `~/.easyserver` только если вам больше не нужны его Local State, identities, trust data или recovery information.

Очистка для конкретных провайдеров:

- [Vast.ai](providers/vastai.md#очистка-аренды)
- [Intelion.cloud](providers/intelion.md#очистка-сервера)

Никогда не используйте удаление Local State вместо очистки ресурсов провайдера. Удаление локальной записи не может удалить удалённый ресурс, который она описывала.
