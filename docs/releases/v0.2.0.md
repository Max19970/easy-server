# EasyServer 0.2.0

EasyServer `0.2.0` makes the interactive TUI the preferred human-facing entrypoint while preserving the CLI as the explicit automation and advanced-command surface.

The release also moves the Provider Plugin SDK and first-party Provider Plugins onto the `0.2.x` compatibility line so interactive provider flows, richer help metadata and host-owned safety semantics can be expressed through public contracts instead of EasyServer internals.

## Highlights

- Plain `easyserver` opens the interactive TUI when stdin/stdout are an interactive terminal.
- `easyserver --help` is the explicit command-mode help path, with hierarchical help for core and provider-owned commands.
- `easyserver --json <command> ...` adds a versioned machine-readable success/error envelope for core automation while keeping human display output as the default.
- The TUI uses a task-first **Home / Servers / Connections / Settings & Support** hierarchy instead of presenting internal subsystems and actions as peer global tabs. **Rent a server** is a guided task from Home/Servers rather than a permanent navigation destination.
- Working pages use a focused breadcrumb layout without a permanent sidebar, with one discoverable arrows/Enter/Esc interaction model and contextual **Actions** instead of route-specific navigation vocabularies. Provider choice fields and credential actions use the same vertical focus model instead of Left/Right toggles.
- Installed Provider Plugins that advertise safe EasyServer package metadata can be selected by human display name without importing unconfigured package code; literal module/path registration remains an Advanced action.
- Provider acquisition remains provider-owned through the generic interactive contract. Vast.ai keeps GPU, price and reliability primary, moves GPU count/verified/result-limit under **More filters**, offers a live GPU-name picker with manual fallback, and preserves image/disk/runtype/label rental options.
- Diagnostics opens with a concise support summary; **View report** uses a bounded width-aware viewer with a visible line position, while **Copy report** always copies the exact same sanitized payload and screen-reader mode exposes that report completely and linearly.
- Servers and Connections now use task language in the ordinary path: a selected server exposes **Start / Stop / Connect** actions, Connect asks for the server service port and optional local port while selecting the provider-declared connection method automatically, and Connections shows local addresses instead of requiring daemon/Session/Endpoint-intent/Access-Method vocabulary. Those exact technical identities and background controls remain under **Technical details / Advanced**.
- Keyboard navigation, narrow-terminal behavior, `NO_COLOR` and Ink screen-reader/linear mode are part of the 0.2.0 release qualification boundary.
- Normal quit, Ctrl+C, thrown TUI errors and two sequential launches in the same terminal restore/retain usable terminal input state on the qualified Windows path.
- The default installation still bundles **zero Provider Plugins**.
- Both supported distribution paths — global npm install and the portable GitHub Release ZIP — are qualified for no-argument TUI launch.

## Compatibility changes from 0.1.x

### No-argument CLI invocation

This is the intentional user-facing compatibility change in `0.2.0`:

- **0.1.x:** scripts or users could treat plain `easyserver` as a command-mode invocation.
- **0.2.0:** plain `easyserver` is the preferred interactive TUI entrypoint when attached to a supported terminal.
- Use `easyserver --help` when help text is the intended command-mode result.
- Existing named commands such as `easyserver plugins list`, `easyserver instances list`, `easyserver connect ...`, `easyserver daemon ...` and `easyserver sessions ...` remain command-mode entrypoints and do not initialize Ink.
- No-argument non-TTY invocation fails deterministically with exit status `1` and an interactive-terminal diagnostic instead of emitting terminal control sequences.

### Machine-readable CLI output

Automation can prefix a named command with `--json` to receive envelope schema version `1`. Successful commands emit one `{ schemaVersion, ok: true, data }` document on stdout and exit `0`; terminal errors emit one `{ schemaVersion, ok: false, error }` document on stderr and exit non-zero. Degraded successful state such as partial inventory remains explicit inside `data` rather than conflicting with the success envelope through a non-zero status. Normalized errors preserve their stable error code, while provider-owned command text is preserved as a namespaced raw transcript instead of being forced into a universal EasyServer schema.

Human-oriented CLI formatting remains the default and is not promoted to a byte-for-byte automation API. See [Machine-readable CLI output](../cli-json.md) for the field and compatibility contract.

### Provider Plugin compatibility line

The release package set is:

- `@easyai101/easyserver-plugin-sdk@0.2.0`;
- `@easyai101/easyserver@0.2.0`;
- `@easyai101/easyserver-plugin-vastai@0.2.0`;
- `@easyai101/easyserver-plugin-intelion@0.2.0`.

First-party packages use `^0.2.0` dependency and manifest compatibility ranges. A Provider Plugin declaring only `^0.1.0` does **not** claim compatibility with the `0.2.x` host/SDK line and must be updated and tested before admission.

### Plugin SDK additions

The `0.2.0` SDK adds public contracts used by the interactive and safety work, including:

- declarative `manifest.credentials` descriptors and credential-readiness metadata;
- provider command mutation-risk metadata (`billable` / `destructive`) for host-owned consent handling;
- structured command help metadata and a dedicated side-effect-free `./easyserver-help` contribution;
- provider CLI usage/result contracts, including affected provider identities for canonical reconciliation;
- presentation-neutral provider interactive flows with form/table/review screens and validated transitions;
- stricter identity semantics for inconclusive provider lookup so temporary failures do not discard canonical EasyServer identity.

Interactive flows do not bypass existing command semantics: a flow assembles arguments for an existing provider command, and the host remains authoritative for safety, mutation dispatch and post-mutation reconciliation.

## Local State and credentials

`0.2.0` does **not** require deleting or recreating EasyServer Local State. Valid `0.1.x` Local State remains readable, canonical `instance:<uuid>` identities are preserved, and existing opaque Secret References continue to address the same OS-backed credentials.

If the primary Local State generation is corrupt but a validated `.recovery` generation exists, the default TUI read path uses the recovery generation. If both generations are invalid, EasyServer fails closed rather than resetting Local State silently.

## Install

### npm

```powershell
npm install --global @easyai101/easyserver@0.2.0
```

Install Provider Plugins separately when needed:

```powershell
npm install --global @easyai101/easyserver-plugin-vastai@0.2.0
# or
npm install --global @easyai101/easyserver-plugin-intelion@0.2.0
```

### GitHub Release ZIP

The Windows release contains:

- `easyserver-0.2.0-windows-x64.zip`;
- `easyserver-0.2.0-SHA256SUMS.txt`.

The portable ZIP contains the core CLI and runtime dependencies but no Provider Plugins or Node.js. See [Install from GitHub Releases](../github-release-install.md).

## Qualified environment

The supported `0.2.0` client target remains deliberately narrow:

- Windows 11 x64;
- Node.js `24.18.1`;
- npm `11.16.0` for npm-based installation and Provider Plugin package installation;
- Windows OpenSSH Client for SSH-backed access.

Linux and macOS remain unqualified support targets pending the separate platform-expansion work; this release does not broaden the platform contract.

The release gate includes deterministic unit/integration tests plus real Windows terminal smoke coverage for wide/narrow rendering, resize, normal quit, Ctrl+C, thrown-error cleanup, `NO_COLOR`, screen-reader mode, global npm installation and the extracted portable ZIP.
