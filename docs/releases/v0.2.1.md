# EasyServer 0.2.1

Version date: **2026-08-17**

EasyServer `0.2.1` is a backward-compatible maintenance release for the `0.2.x` line. It expands the release-qualified client platforms to Ubuntu 24.04 x64 and macOS 15 arm64, hardens OpenSSH failure handling on Unix, fixes a normal Vast.ai post-destroy observation edge case, and improves public documentation and release-note publishing.

No migration is required from `0.2.0`. Existing valid `0.2.x` Local State, Secret References, CLI workflows, and Provider Plugins that declare `^0.2.0` compatibility remain valid.

This page is historical release documentation. For current usage, start at [Getting started](../getting-started.md) or the [documentation index](../README.md).

## Highlights

### Ubuntu 24.04 x64 and macOS 15 arm64 are now qualified

Starting with `0.2.1`, the supported client-platform matrix is:

- Windows 11 x64;
- Ubuntu 24.04 x64;
- macOS 15 arm64.

The newly qualified Ubuntu and macOS release gates continuously exercise the full test suite, publishable package surface, clean packaged/global Provider Plugin installation, a real operating-system keyring create/read/delete round trip, and the system OpenSSH/`ssh-keyscan` prerequisites.

The Unix qualification work also removed platform-specific timing assumptions from connection and state-lock regression tests so the release gate verifies behavior rather than scheduler speed.

See [Supported platforms](../supported-platforms.md) for the exact OS, architecture, runtime, Secret Store, OpenSSH, and headless-Linux prerequisites. The portable GitHub Release ZIP remains Windows x64-only; Ubuntu and macOS use the npm package path.

### Safer OpenSSH failures on Unix

OpenSSH process and pipe shutdown races no longer expose raw Node.js transport errors such as `EPIPE` or `ERR_STREAM_PREMATURE_CLOSE` to EasyServer users.

EasyServer now keeps the public writable stream separate from the child process stdin pipe, captures internal stdin failures, and reports the existing normalized EasyServer connection failure after the OpenSSH process closes. Regression coverage includes a large in-flight write during abrupt process termination.

Explicit connection close/cancellation behavior remains unchanged.

### Vast.ai destroy convergence no longer treats absence as malformed data

Immediately after a successful Vast.ai destroy, the provider can report the instance as `null` or an empty instance list. EasyServer now treats those documented missing-instance shapes as normal absence instead of surfacing a misleading `Vast.ai instance must be an object` plugin failure.

Malformed non-empty payloads still fail closed.

### Release notes work correctly on GitHub Releases

Source release notes continue to use convenient repository-relative documentation links. During tag-driven GitHub Release publication, EasyServer now parses the Markdown and rewrites actual relative link/image/definition destinations to URLs pinned to the exact release commit.

Anchors and external URLs keep their intended meaning, repository traversal is rejected, and unrelated Markdown remains unchanged. Tag verification and release-asset integrity checks are unchanged.

### Public documentation overhaul and Russian localization

The public documentation was reorganized around user tasks and durable contracts, with clearer entry points for installation, connections, background connections, Provider Plugin authoring/reference, security, package lifecycle, compatibility, and platform support.

A structured Russian localization now mirrors the public documentation set under `docs/ru/`, with Russian repository-level README, contributing, and security guidance. English remains the canonical contract language; localization rules are documented explicitly.

### Small CLI help correction

The `sessions close` help example now uses a valid bare Session ID instead of the invalid `session:<uuid>` placeholder form.

## Package set and compatibility

The released package set is:

- `@easyai101/easyserver-plugin-sdk@0.2.1`;
- `@easyai101/easyserver@0.2.1`;
- `@easyai101/easyserver-plugin-vastai@0.2.1`;
- `@easyai101/easyserver-plugin-intelion@0.2.1`.

Package and Provider Plugin compatibility ranges intentionally remain on `^0.2.0`. This keeps `0.2.1` inside the existing `0.2.x` compatibility line rather than requiring plugins or users to update solely because of the patch release.

Valid `0.2.0` Local State remains supported; there is no state migration for this release.

## Install this historical version

### npm

```text
npm install --global @easyai101/easyserver@0.2.1
npm install --global @easyai101/easyserver-plugin-vastai@0.2.1
# or
npm install --global @easyai101/easyserver-plugin-intelion@0.2.1
```

### GitHub Release

Release `v0.2.1` publishes the Windows x64 portable artifacts:

```text
easyserver-0.2.1-windows-x64.zip
easyserver-0.2.1-SHA256SUMS.txt
```

The portable bundle contains the core CLI/runtime dependencies but not Node.js or Provider Plugins.

## Release environment

Qualified runtime for this release:

- Node.js `24.18.1`;
- npm `11.16.0` for npm/package installation.

Qualified client targets:

- Windows 11 x64 with Windows Credential Manager and Windows OpenSSH Client;
- Ubuntu 24.04 x64 with a working Linux Secret Store path and system OpenSSH;
- macOS 15 arm64 with macOS Keychain and system OpenSSH.

For Linux, the keyring integration first attempts D-Bus Secret Service and falls back to the Linux kernel keyring through keyutils when Secret Service is unavailable. See [Supported platforms](../supported-platforms.md) for headless and unqualified-environment boundaries.
