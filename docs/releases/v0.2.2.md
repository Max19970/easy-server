# EasyServer 0.2.2

Version date: **2026-08-17**

EasyServer `0.2.2` is a backward-compatible distribution release for the `0.2.x` line. Its main change is that every release-qualified client platform now receives a first-class portable GitHub Release artifact, with release automation enforcing complete platform coverage before publication.

No migration is required from `0.2.1`. Existing valid `0.2.x` Local State, Secret References, CLI workflows, and Provider Plugins that declare `^0.2.0` compatibility remain valid.

This page is historical release documentation. For current usage, start at [Getting started](../getting-started.md) or the [documentation index](../README.md).

## Highlights

### Portable GitHub Release downloads now cover every qualified platform

Starting with `0.2.2`, GitHub Releases publish a verified portable artifact for every release-qualified client target:

- Windows 11 x64 — `easyserver-0.2.2-windows-x64.zip`;
- Ubuntu 24.04 x64 — `easyserver-0.2.2-linux-x64.tar.gz`;
- macOS 15 arm64 — `easyserver-0.2.2-macos-arm64.tar.gz`.

A shared `easyserver-0.2.2-SHA256SUMS.txt` manifest contains the SHA-256 digest for every portable artifact.

The bundles contain the EasyServer CLI and production runtime dependencies, but intentionally do not bundle Node.js or Provider Plugins. Vast.ai and Intelion.cloud can be installed later into the extracted portable prefix using npm.

See [Install from GitHub Releases](../github-release-install.md) for platform-specific download, checksum, extraction, and Provider Plugin installation instructions.

### Portable artifacts are built and tested on their native operating systems

The release-target contract defines the supported artifact matrix once and drives both CI and tag publication. Each qualified runner builds and verifies its own native bundle instead of producing cross-platform archives from one host.

The native artifact smoke verifies:

- the launcher starts outside the repository;
- `--version` reports the exact release version;
- `--help` remains functional;
- a fresh bundle works with zero configured Provider Plugins;
- first-party Vast.ai and Intelion.cloud plugins can be installed into and loaded from the extracted portable prefix.

### Incomplete platform coverage now blocks release publication

Release automation now treats portable artifact coverage as a release invariant: every qualified platform must have exactly one defined artifact format, and the final publication step requires the complete expected artifact set before a GitHub Release can be created.

Tests also verify that CI and release workflows continue to derive their matrices from the authoritative release-target contract, preventing a future platform-support change from silently drifting away from the published asset set.

### Published artifacts receive post-publication smoke verification

After GitHub Release creation, native platform jobs download the real published artifact and checksum manifest and verify the public distribution surface rather than relying only on pre-publication build outputs.

This includes SHA-256 validation and fresh external-directory execution on each qualified platform.

### Windows release validation is more resilient under host contention

The Windows release gate no longer relies on a short wall-clock race to prove that Secret Store work happens outside the Local State lock. The regression now checks the lock invariant directly.

Temporary SSH credential ownership also avoids repeatedly spawning PowerShell after the current process identity has already been verified. The current process identity is cached only after a successful stable OS probe; scavenging of historical credential owners still revalidates their PID and process identity before deletion, preserving the fail-closed PID-reuse boundary.

## Package set and compatibility

The released package set is:

- `@easyai101/easyserver-plugin-sdk@0.2.2`;
- `@easyai101/easyserver@0.2.2`;
- `@easyai101/easyserver-plugin-vastai@0.2.2`;
- `@easyai101/easyserver-plugin-intelion@0.2.2`.

Package and Provider Plugin compatibility ranges intentionally remain on `^0.2.0`. This keeps `0.2.2` inside the existing `0.2.x` compatibility line rather than requiring plugins or users to update solely because of the patch release.

Valid `0.2.x` Local State remains supported; there is no state migration for this release.

## Install this historical version

### npm

```text
npm install --global @easyai101/easyserver@0.2.2
npm install --global @easyai101/easyserver-plugin-vastai@0.2.2
# or
npm install --global @easyai101/easyserver-plugin-intelion@0.2.2
```

### GitHub Release

Release `v0.2.2` publishes:

```text
easyserver-0.2.2-windows-x64.zip
easyserver-0.2.2-linux-x64.tar.gz
easyserver-0.2.2-macos-arm64.tar.gz
easyserver-0.2.2-SHA256SUMS.txt
```

Verify the matching checksum before extracting the bundle. See [Install from GitHub Releases](../github-release-install.md) for exact commands on each platform.

## Release environment

Qualified runtime for this release:

- Node.js `24.18.1`;
- npm `11.16.0` for npm/package and Provider Plugin installation.

Qualified client targets:

- Windows 11 x64 with Windows Credential Manager and Windows OpenSSH Client;
- Ubuntu 24.04 x64 with a working Linux Secret Store path and system OpenSSH;
- macOS 15 arm64 with macOS Keychain and system OpenSSH.

For Linux, the keyring integration first attempts D-Bus Secret Service and falls back to the Linux kernel keyring through keyutils when Secret Service is unavailable. See [Supported platforms](../supported-platforms.md) for headless and unqualified-environment boundaries.
