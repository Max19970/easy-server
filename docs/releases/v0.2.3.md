# EasyServer 0.2.3

Version date: **2026-08-18**

EasyServer `0.2.3` is a backward-compatible TUI/QoL and code-health release for the `0.2.x` line. It keeps the accepted task-first interaction model while making ordinary terminal use calmer, more actionable, more visually coherent, and more robust under connection and provider failures.

No migration is required from `0.2.2`. Existing valid `0.2.x` Local State, Secret References, saved background connections, CLI workflows, and Provider Plugins that declare `^0.2.0` compatibility remain valid. TUI appearance preferences are optional and are stored separately from Local State.

This page is historical release documentation. For current usage, start at [Getting started](../getting-started.md) or the [documentation index](../README.md).

## Highlights

### Calmer, more truthful task-first TUI

Routine navigation no longer fills scarce terminal rows with redundant status narration such as opened/selected/action-menu messages. The visible breadcrumb, focus marker, and one contextual keyboard hint carry ordinary navigation state, while status text is reserved for feedback that can change the next decision.

Empty and dependency states now advertise only actions that actually exist. In particular:

- Providers does not tell you to add an installed provider when no discoverable package is available;
- Rent server can route directly to Providers when acquisition is not configured;
- Connections can route directly to Rent a server when no server exists yet.

The ordinary keyboard model remains arrows + `Enter` + `Esc`. Legacy route-specific letter/number paths that duplicated visible Actions were removed; the retained refresh accelerator resolves through the same semantic action availability as the visible menu.

### Provider-owned interactive flows are more accessible

Generic provider choice pickers now preserve the complete linear choice list in screen-reader mode and correctly budget wrapped/long labels inside visual terminal viewports. The same generic renderer remains provider-domain-agnostic while behaving consistently at qualified terminal sizes.

### One coherent visual language

Core screens, contextual actions, operation drawers, and provider-owned guided flows now share one restrained semantic appearance contract:

- one accent/focus role;
- muted secondary information;
- stable success, warning, danger, and degraded roles;
- explicit text/focus markers so color is never the only carrier of meaning.

Guided provider workflows no longer drop into an unstyled monochrome sub-surface when the surrounding EasyServer TUI is color-enabled.

### Resource views are easier to scan

Servers, Connections, Providers, and generic provider tables now use responsive terminal-aware layouts instead of relying on long delimiter-heavy rows.

At narrow widths the most important identity/state information is preserved first. At wider widths state and secondary fields receive stable columns, and the main working measure is kept readable instead of stretching text across the full terminal width.

The release remains qualified at `60x20`, `80x24`, and `120x40`.

### Constrained Appearance customization

Open **Settings & Support → Appearance** to choose:

- accent: Cyan (default), Blue, Magenta, or White;
- density: Comfortable (default) or Compact;
- **Reset to defaults**.

Accent affects brand/focus emphasis only; success, warning, and danger semantics remain fixed. Compact density reduces nonessential vertical gaps without removing warnings, confirmations, recovery actions, or technical information.

Preferences persist in `~/.easyserver/appearance.json`, separately from EasyServer Local State. Invalid or corrupt appearance data falls back safely to Cyan + Comfortable. `NO_COLOR` remains an absolute runtime override and screen-reader output remains semantic rather than style-dependent.

### Connection recovery no longer depends on English error wording

Connection failures now carry a small internal typed cause such as SSH authentication rejection, trusted-host mismatch, fingerprint acquisition failure, SSH readiness, forwarding policy, remote-service reachability, local bind conflict, or unexpected transport closure.

Foreground late failures and saved background connection failures retain that safe machine-readable cause after the original async operation ends. Retry/Edit/Review-trust decisions use the typed cause rather than regex-matching human error strings, so copy changes cannot silently change recovery behavior.

Raw OpenSSH stderr, credentials, and unsafe provider-controlled text are still not retained for TUI recovery.

### Code-health and test gates are stricter

The TUI frontend was decomposed into task-owned Servers, Connections, Providers/Rent, and Diagnostics presentation modules with shared semantic action builders. The monolithic TUI integration test was split by behavior domain while preserving the same scenarios and common fixtures.

Workspace-local tests now build current source before executing compiled tests, preventing stale ignored `dist` output from producing false passes. TypeScript unused-local/unused-parameter checks are part of the compiler gate.

First-party Vast.ai and Intelion.cloud provider clients now consume one canonical bounded/sanitized provider-error safety implementation at build time. Provider-specific response parsing stays local to each plugin, and the published plugin packages remain self-contained with the existing `^0.2.0` SDK compatibility range.

## Package set and compatibility

The released package set is:

- `@easyai101/easyserver-plugin-sdk@0.2.3`;
- `@easyai101/easyserver@0.2.3`;
- `@easyai101/easyserver-plugin-vastai@0.2.3`;
- `@easyai101/easyserver-plugin-intelion@0.2.3`.

Package and Provider Plugin compatibility ranges intentionally remain on `^0.2.0`. This keeps `0.2.3` inside the existing `0.2.x` compatibility line rather than forcing plugin or configuration churn for a patch release.

Valid `0.2.x` Local State remains supported; there is no state migration for this release.

## Install this historical version

### npm

```text
npm install --global @easyai101/easyserver@0.2.3
npm install --global @easyai101/easyserver-plugin-vastai@0.2.3
# or
npm install --global @easyai101/easyserver-plugin-intelion@0.2.3
```

### GitHub Release

Release `v0.2.3` publishes:

```text
easyserver-0.2.3-windows-x64.zip
easyserver-0.2.3-linux-x64.tar.gz
easyserver-0.2.3-macos-arm64.tar.gz
easyserver-0.2.3-SHA256SUMS.txt
```

Verify the matching checksum before extracting the bundle. See [Install from GitHub Releases](../github-release-install.md) for exact commands on each platform.

## Release environment

Qualified runtime for this release:

- Node.js `24.18.1`;
- npm `11.16.0` for npm/package and Provider Plugin installation.

Qualified client targets:

- Windows 11 x64 with Windows Credential Manager and Windows OpenSSH Client;
- Ubuntu 24.04 x64 with a working Linux Secret Store path and system OpenSSH;
- macOS 15 arm64 with macOS Keychain and system OpenSSH.

The portable release contract remains unchanged from `0.2.2`: every qualified platform must build and smoke its own native artifact before publication, all native jobs must succeed, one SHA-256 manifest must cover the complete artifact set, and post-publication jobs verify the real public downloads.
