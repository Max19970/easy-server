# EasyServer 0.1.0

Released: **2026-08-10**

EasyServer `0.1.0` was the first public release: a provider-independent CLI for acquiring, managing, and locally accessing rented compute while keeping provider-specific acquisition in separately installed Provider Plugins.

This page is historical release documentation. For current EasyServer usage, use the [documentation index](../README.md).

## Highlights

- First-party Provider Plugins for **Vast.ai** and **Intelion.cloud**.
- Shared server inventory and normalized lifecycle operations across providers.
- Generic local TCP Endpoints over SSH-backed provider access.
- Foreground connections and daemon-owned persistent Connection Sessions.
- Explicit SSH host-key trust on first use; changed trusted keys fail closed.
- Provider credentials stored through the OS-backed Secret Store rather than raw Local State.
- Public `@easyai101/easyserver-plugin-sdk` package for third-party Provider Plugins.
- Minimal core installation with **zero Provider Plugins bundled by default**.

## Distribution

### npm

The `0.1.0` package set was published as:

```text
@easyai101/easyserver@0.1.0
@easyai101/easyserver-plugin-sdk@0.1.0
@easyai101/easyserver-plugin-vastai@0.1.0
@easyai101/easyserver-plugin-intelion@0.1.0
```

Provider Plugins were separately installed opt-in packages rather than transitive dependencies of the CLI.

### GitHub Release

Release `v0.1.0` published:

```text
easyserver-0.1.0-windows-x64.zip
easyserver-0.1.0-SHA256SUMS.txt
```

The portable ZIP contained the core CLI/runtime dependencies but did not bundle Node.js or Provider Plugins.

## Release environment

The supported `0.1.0` client target was **Windows 11 x64** with:

- Node.js `24.18.1`;
- npm `11.16.0` for npm/package installation;
- Windows OpenSSH Client for SSH-backed access.

Linux and macOS were not part of the `0.1.0` release support contract.

## Important 0.1.0 limitations

- EasyServer managed compute/access, not workload installation or orchestration.
- Local access was raw TCP forwarding rather than HTTP path routing, VPN, or application proxying.
- Provider billing remained provider-specific; stopped compute did not universally mean billing had ended.
- Provider Plugins ran as trusted in-process code rather than sandboxed extensions.
- Vast.ai SSH access required the private identity corresponding to the account-level public key to be discoverable through a standard OpenSSH identity file or `ssh-agent`; EasyServer's managed path did not use the user's `~/.ssh/config` as its identity source.
